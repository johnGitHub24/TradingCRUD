系統啟動與 StartupInfoLogger

從 Gradle／IntelliJ 到 Console 印出常用 URL 的完整 runtime 路徑

Spring Boot 3.2 Java 21 ApplicationReadyEvent startup.info.* :8083
一句話： bootRun／IntelliJ 只負責把 TradingCrudApplication 拉起來； Spring 把 application.yml 灌進 Environment 並建好 Bean； DataSeeder 先種 admin；Tomcat 開 :8083 後發 ApplicationReadyEvent； StartupInfoLogger 再依 startup.info.* 決定 Console 印哪些連結。

1. 誰觸發啟動（三種入口，本質相同）

入口實際做的事
IntelliJ TradingCrudApplication 直接跑 main，主類 com.trading.crud.TradingCrudApplication
IntelliJ / CLI gradlew bootRun Boot plugin 用 build.gradle 的 springBoot.mainClass 起同一支 main
scripts/start.ps1 新視窗跑 gradlew bootRun，再另開 Vite :5173（前端與後端無關） 
springBoot {
    mainClass = 'com.trading.crud.TradingCrudApplication'
}

tasks.named('bootRun') {
    group = 'application'
    description = 'Run backend at http://localhost:8083'
}
bootRun 不會解析 startup.info.*； YAML 是 JVM 起來後由 Spring 讀的。

五個階段速覽

A

B

E

3. YAML 何時進 Runtime

src/main/resources/application.yml 進 classpath；Spring 掛入 Environment（優先序大致：命令列 > 環境變數 > YAML）。

startup:
  info:
    enabled: true
    project-name: TradingCRUD
    frontend: vite
    auth: true
    h2: true
    api-docs: true
    frontend-port: 5173
    home-path: /orders
    login-path: /login
    default-user: admin
    default-pass: admin123
YAML用途
startup.info.enabledfalse 則整段不印
startup.info.project-name框標題
server.port組 http://localhost:{port}
startup.info.frontendnone / static / vite
h2 / api-docs / auth條件區塊開關
spring.datasource.url印 H2 JDBC（若 h2=true）
改 YAML 不必改 Java。 StartupInfoLogger 只做「讀 Environment → 印字」。

為何聽 ApplicationReadyEvent？

  • 建構子／@PostConstruct 時 Tomcat 可能還沒綁埠，印 URL 太早會誤導。
  • CommandLineRunner（DataSeeder）在 Ready 之前跑：先有 admin，再開門，再印連結。

順序：Context refresh → CommandLineRunner → WebServer start → ApplicationReadyEvent

Gradle

編譯、哪個 main、bootRun、前端腳本

YAML + Logger

埠、DB、JWT、Console 印什麼。
Logger 不啟動前端、不驗證 URL。

start.ps1 腳本層也印一輪 URL； StartupInfoLogger 是後端就緒後再印（runtime）。來源不同、內容刻意對齊。

7. 啟動後才發生的業務路徑

HTTP :8083 → Security Filter → Controller → Service → JPA / H2

這與 startup.info 無關；後者只影響開發 Console 輸出。

測試要安靜啟動可設：

startup.info.enabled=false

8. 其他專案是否同一作法？

是。 同一條鏈： main → YAML → Bean →（可選）CommandLineRunner → Tomcat → Ready → 印 URL。 差異只在 YAML／套件名／有無種子／有無前端。
專案portfrontendh2api-docs備註
TradingCRUD 8083vite :5173truetrue DataSeeder + JWT
TradingPagingList 8091vite :5174truetrue 產品種子；無 auth
TradingFinTech 8092nonetruetrue API-only
TradingPrometheusActuator 8090nonefalsefalse extra-paths 印 prometheus

套用三步驟

  1. 複製／改 package 的 StartupInfoLogger.java
  2. application.yml 貼上對應 startup.info.*
  3. （可選）build.gradle 指定 mainClass + bootRun
