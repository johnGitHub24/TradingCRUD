# TradingCRUD 驗證設計

> **用途：** 說明請求驗證、授權、業務規則、錯誤回應的完整分層設計。  
> **對照：** `GlobalExceptionHandler`、`ErrorCodes`、各 DTO `@Valid` 註解。

---

## 1. 驗證分層總覽

```text
┌─────────────────────────────────────────────────────────────┐
│ L1 傳輸層：HTTP Method / Content-Type / JWT Bearer           │
│     Spring Security Filter Chain + @PreAuthorize             │
├─────────────────────────────────────────────────────────────┤
│ L2 格式層：Bean Validation（@Valid on DTO）                  │
│     缺欄位、型別錯誤、值域非法 → 400 VALIDATION_FAILED       │
├─────────────────────────────────────────────────────────────┤
│ L3 業務層：Service 規則判斷                                   │
│     重複 clientOrderId → 409 DUPLICATE_ORDER                 │
│     訂單不存在 → 404 ORDER_NOT_FOUND                          │
├─────────────────────────────────────────────────────────────┤
│ L4 資料層：DB 約束（UNIQUE、NOT NULL）                        │
│     最後防線；正常情況 L3 已攔截                               │
└─────────────────────────────────────────────────────────────┘
```

---

## 2. 認證與授權（L1）

### 2.1 JWT 流程

```text
POST /api/v1/auth/login { username, password }
  → AuthenticationManager 驗證 BCrypt 密碼
  → JwtService.generateToken() 產生 HS256 Token
  → 回傳 { accessToken, tokenType, expiresIn, username, role }

後續請求：
  Authorization: Bearer <token>
  → JwtAuthenticationFilter 解析 Token
  → SecurityContext 設定 Authentication
  → @PreAuthorize 檢查角色
```

### 2.2 端點權限矩陣

| 端點 | 公開 | USER（已登入） | ADMIN |
|------|------|----------------|-------|
| POST `/auth/login` | ✅ | — | — |
| GET `/auth/me` | — | ✅ | ✅ |
| GET `/orders` | — | ✅ | ✅ |
| GET `/orders/{id}` | — | ✅ | ✅ |
| POST `/orders` | — | — | ✅ |
| PUT `/orders/{id}` | — | — | ✅ |
| DELETE `/orders/{id}` | — | — | ✅ |
| POST/DELETE `/orders/batch` | — | — | ✅ |

### 2.3 錯誤回應

| 情境 | HTTP | errorCode |
|------|------|-----------|
| 未帶 Token | 401 | UNAUTHORIZED |
| Token 無效/過期 | 401 | UNAUTHORIZED |
| 帳密錯誤 | 401 | BAD_CREDENTIALS |
| 權限不足 | 403 | FORBIDDEN |

**測試 Case：** SEC-001、SEC-002、AUTH-002

## 3. Bean Validation（L2）

### 3.1 LoginRequest

| 欄位 | 規則 | 錯誤訊息 |
|------|------|----------|
| username | `@NotBlank` | username 不可為空 |
| password | `@NotBlank` | password 不可為空 |

**Case：** AUTH-003

### 3.2 CreateOrderRequest

| 欄位 | 規則 | 說明 |
|------|------|------|
| clientOrderId | `@NotBlank`, `@Size(max=64)` | 業務冪等 ID |
| symbol | `@NotBlank`, `@Size(max=20)` | 交易標的 |
| side | `@NotNull` | BUY / SELL enum |
| quantity | `@NotNull`, `@DecimalMin("0.0", inclusive=false)` | 必須 > 0 |
| price | `@NotNull`, `@DecimalMin("0.0", inclusive=false)` | 必須 > 0 |

**Case：** ORDER-003、ORDER-004、DTO-002、DTO-003

### 3.3 UpdateOrderRequest

| 欄位 | 規則 |
|------|------|
| symbol | `@NotBlank`, `@Size(max=20)` |
| side | `@NotNull` |
| quantity | `@NotNull`, `@DecimalMin` > 0 |
| price | `@NotNull`, `@DecimalMin` > 0 |
| status | `@NotNull` |

### 3.4 BatchCreateRequest / BatchDeleteRequest

| 欄位 | 規則 | Case |
|------|------|------|
| orders | `@NotEmpty` | BATCH-003 |
| ids | `@NotEmpty` | BATCH-003 |

### 3.5 驗證失敗回應格式

```json
{
  "type": "about:blank",
  "title": "Validation Failed",
  "status": 400,
  "detail": "Request validation failed",
  "instance": "/api/v1/orders",
  "errorCode": "VALIDATION_FAILED",
  "errors": [
    { "field": "clientOrderId", "message": "clientOrderId 不可為空" }
  ]
}
```

Content-Type：`application/problem+json`（RFC 7807 風格）

## 4. 業務規則驗證（L3）

| 規則 | 位置 | 例外 | HTTP | errorCode |
|------|------|------|------|-----------|
| clientOrderId 不可重複 | OrderService.create | DuplicateResourceException | 409 | DUPLICATE_ORDER |
| 訂單必須存在 | OrderService.findOrThrow | ResourceNotFoundException | 404 | ORDER_NOT_FOUND |
| 批次內重複 clientOrderId | OrderService.batchCreate | 記入 failures | 207 | — |
| 批次部分 DB 重複 | OrderService.batchCreate | 記入 failures | 207 | — |
| 批次刪除不存在 ID | OrderService.batchDelete | 記入 failures | 207 | — |

**批次回應範例（207 Multi-Status）：**

```json
{
  "requested": 2,
  "succeeded": 1,
  "failed": 1,
  "createdIds": [42],
  "failures": [
    { "index": 1, "reference": "dup-001", "reason": "clientOrderId already exists" }
  ]
}
```

## 5. 資料庫約束（L4）

| 約束 | 欄位 | 由誰先攔截 |
|------|------|-----------|
| UNIQUE | orders.client_order_id | Service.existsByClientOrderId |
| UNIQUE | app_users.username | DataSeeder 啟動檢查 |
| NOT NULL | 各必填欄位 | Bean Validation + JPA |

## 6. 前端驗證對照

| 層 | Vue 實作 | 說明 |
|----|----------|------|
| 表單 | HTML5 `required`、`min`、`step` | 第一道防線，減少無效請求 |
| API | axios 攔截器 401 處理 | Token 失效自動登出 |
| 角色 | `auth.isAdmin` 控制按鈕顯示 | UI 層隱藏，後端仍 @PreAuthorize 把關 |

> **重要：** 前端驗證僅改善 UX，**不可取代後端驗證**。
